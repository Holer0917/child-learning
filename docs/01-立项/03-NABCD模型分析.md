# 口算小达人 · NABCD 模型分析

> **对应课程交付物**：第一次课 —— 「确定需求分析的 NABCD 模型」
> **模型说明**：NABCD 由 Need（需求）、Approach（做法）、Benefit（好处）、Competitors（竞争）、Delivery（推广）五要素构成，用于回答"**为什么值得做这个软件**"。
> 本模型聚焦"原始目的"，不做功能细化——功能细化见 [需求规格说明书](../02-需求分析/)。

| 要素 | 一句话回答 |
|---|---|
| **N**eed 需求 | 家长每天被迫花 15 分钟做**出题、抄题、批改、抄错题**这件重复劳动 |
| **A**pproach 做法 | 参数化**出题引擎**自动组卷 + 浏览器原生**自动批改与 A4 打印** + 本地**错题归档与举一反三** |
| **B**enefit 好处 | 每天 15 分钟 → 30 秒；错题自动成册；学情看得见；三年一贯不用换软件 |
| **C**ompetitors 竞争 | 现有口算 App 重"屏幕刷题"、轻"纸质作业"，且核心功能收费；**A4 打印出卷**是我们的差异化切口 |
| **D**elivery 推广 | 家长群 / 班级群口碑传播 → Gitee Pages 零门槛在线试用 → 老师背书进入班级 |

---

## 一、N — Need（需求）

### 1.1 原始需求的出处

本项目的需求不是凭空想象的，它直接来自课程选题参考第 2 题的场景描述：

> "小明的妈妈近期很郁闷，小明上小学后，老师要求每天完成 30 道口算题，每天出题改题成了一个大负担，'有个可以出题的软件就好了'小明妈妈这么想。"

### 1.2 需求的进一步验证：访谈真实家长

为避免"想当然"，小组在立项会后访谈了 **3 位真实家长**（组员亲友，均为小学在读孩子的家长），
访谈记录见 [需求分析 · 用户访谈原始记录](../02-需求分析/03-用户访谈原始记录.md)。核心结论如下：

| 受访者 | 孩子年级 | 原话摘录 | 提炼出的需求 |
|---|---|---|---|
| 家长 A | 一年级 | "每天下班回来先给他出 30 道题，我手写，他做完我再一道道对，**前后半小时没了**。" | 出题与批改必须自动化 |
| 家长 A | 一年级 | "老师要**交本子**，我在手机上让他做完了，还得再抄一遍。" | **必须能打印成纸质卷** |
| 家长 B | 三年级 | "**除法老错**，我想让他多练除法，可买的口算题卡都是加减乘除混在一起的。" | 必须能**按知识点定向出题** |
| 家长 C | 二年级 | "错题我给他抄在一个本子上，**抄了半本也没见他翻过**。" | 错题要**自动归档、可重练** |
| 家长 B | 三年级 | "（问：愿意花钱买吗）**如果好用，几十块钱一年能接受**，但得先让我白试试。" | 需**免费试用**，核心功能不能锁 |
| 家长 C | 二年级 | "最烦的是一堆 App 要**注册、要填手机号**，我就想打开就能用。" | 免注册、低门槛 |

### 1.3 需求本质：这是一个"家长的时间账"问题

把访谈结论抽象一层，本项目的**原始目的**（唯一靶心）是：

> **把家长每天花在口算作业上的重复劳动时间，从 15~30 分钟压缩到 1 分钟以内。**

这里的需求**不是**"做一个学习软件"——那是手段；
需求是"**让家长从每天必须亲自做的低价值重复劳动里解放出来**"。
围绕这个靶心，其它一切都只是实现手段：

- 为什么要自动批改？——因为批改占掉家长 5 分钟；
- 为什么要打印？——因为抄题占掉家长 10 分钟，而且老师要纸质本子；
- 为什么要错题本？——因为手抄错题是又一项重复劳动，且抄完就废；
- 为什么要按知识点出题？——因为"孩子除法老错"时，家长需要定向加练，而买来的题卡做不到。

### 1.4 痛点强度评估

| 痛点 | 发生频率 | 单次耗时 | 是否有替代方案 | 痛感 |
|---|---|---|---|---|
| 手工出题 | **每天 1 次** | 5–10 分钟 | 买口算题卡（但不针对薄弱点、量固定） | 🔴 高 |
| 手工批改 | **每天 1 次** | 3–5 分钟 | 无（家长必须逐题看） | 🔴 高 |
| 手抄错题 | 每次练习后 | 2–3 分钟 | 无（抄了也不看） | 🟡 中 |
| 判断学情 | 想复盘时 | 10+ 分钟 | 无（凭感觉） | 🟡 中 |

**结论**：这是一个**高频（每天）、刚需（老师强制布置）、无良好替代方案**的痛点。
符合 NABCD 对"需求"的要求——它回答的是"为什么要做"，而不是"做什么功能"。

## 二、A — Approach（做法）

我们解决这个痛点所依赖的"招数"，分为**技术招数**和**产品设计招数**两类。

### 2.1 技术招数

| # | 招数 | 具体做法 | 解决哪个痛点 |
|---|---|---|---|
| A1 | **参数化出题引擎** | 把每个知识点建模为"约束 + 生成规则 + 干扰项规则"，如"20 以内进位加法"约束为 `a+b>10 且 a,b≤9`，随机生成后按知识点去重，保证一份卷子内不重复 | 手工出题 |
| A2 | **即时判分** | 每道题作答后立即比对答案并给出对错反馈，无需家长介入 | 手工批改 |
| A3 | **浏览器原生打印（`@media print`）** | 用专门的打印样式表把页面渲染成 A4 版式，一键出卷，含独立答案页 | **纸质作业刚需** |
| A4 | **举一反三算法** | 记录错题的"知识点 + 操作数特征"，调用同一生成器产出 3 道同型变式题 | 错题重练 |
| A5 | **localStorage 本地持久化** | 所有档案、记录、错题存在浏览器本地，**数据不出本机** | 免注册 + 隐私 |
| A6 | **PWA（Manifest + Service Worker）** | 支持"添加到主屏幕"与离线访问，体验接近原生 App，但**零安装成本** | 使用门槛 |
| A7 | **手写 SVG 图表** | 学情统计用原生 SVG 绘制，不引入图表库，体积小、配色可控 | 性能与可访问性 |

### 2.2 产品设计招数

| # | 招数 | 具体做法 |
|---|---|---|
| A8 | **"先出卷、后答题"的双通道设计** | 主入口直接是「出卷」——家长 3 步（选年级 → 选题量 → 点打印）拿到纸质卷；屏幕答题作为练习通道并存。**不做"必须注册才能用"的流程** |
| A9 | **按知识点定向出题** | 提供 24 个知识点的勾选面板，家长可只勾"除法"，精准打击薄弱环节 |
| A10 | **难度自适应** | 依据近期正确率自动推荐下一组题的难度档位，避免"太简单没意思 / 太难哭" |
| A11 | **多孩子档案** | 一台设备建多个档案，各档案的记录、错题、统计完全隔离 |
| A12 | **零门槛试用** | 打开网页即用，不注册、不登录、不看广告、核心功能不锁 |

### 2.3 招数的可行性论证

| 招数 | 可行性 | 说明 |
|---|---|---|
| A1 出题引擎 | ✅ 高 | 纯逻辑代码，无外部依赖；1–3 年级知识点边界清晰，可枚举 |
| A3 打印 | ✅ 高 | 浏览器原生能力，`@page` + `@media print` 成熟稳定 |
| A4 举一反三 | ✅ 高 | 与 A1 共用生成器，仅需反向解析题目参数 |
| A5 本地存储 | ✅ 高 | localStorage 容量约 5MB，纯文本记录足够存数年 |
| A6 PWA | ✅ 中 | 需 HTTPS（Gitee Pages 满足）；iOS 支持有限但不影响核心功能 |
| A7 手写 SVG | ✅ 中 | 需自行实现坐标轴与折线，工作量可控（约 300 行） |

## 三、B — Benefit（好处）

### 3.1 对家长（主要用户）

| 好处 | 量化 |
|---|---|
| **时间成本骤降** | 每天 15 分钟 → **约 30 秒**（点三下出卷，点一下批改）；一学期（按 100 天计）可省 **约 25 小时** |
| **批改零负担** | 屏幕练习自动判分；纸质卷配套答案页，家长只需扫一眼对错 |
| **精准加练** | 孩子"除法老错"时，勾选除法即可连出 20 道，不再被题卡"混着出"绑架 |
| **错题不再白抄** | 错题自动进本，一键重练；举一反三自动出变式题，验证是否真会了 |
| **学情可视化** | 正确率趋势、知识点掌握度一目了然，家长会上有据可依 |
| **省钱** | 免费使用核心功能；相比每学期买 2~3 本口算题卡（约 30~50 元），三年可省 **200~300 元** |

### 3.2 对学生（直接用户）

| 好处 | 说明 |
|---|---|
| **练习即时反馈** | 答对/答错立刻知道，比"做完等家长批"的反馈链路短得多 |
| **难度不挫败** | 自适应难度让孩子始终处在"跳一跳够得着"的区间，不易产生厌学情绪 |
| **成就感** | 打卡天数、徽章、正确率进步曲线，把练习变成可见的成长 |
| **护眼** | 主通道是**纸质卷**，屏幕时间可控，不增加近视风险 |

### 3.3 对老师（次要用户）

| 好处 | 说明 |
|---|---|
| **作业可标准化** | 可统一出卷发给全班，题量、知识点可控 |
| **纸质作业无缝衔接** | 打印即可收本子，不改变现有批改与收缴流程 |
| **学情反馈** | 家长可依据统计结果与老师沟通孩子的薄弱点 |

### 3.4 社会价值

- **数据隐私友好**：所有学生数据留在本机，不上传服务器，无第三方追踪——在"儿童数据合规"日趋严格的当下，这是一个真实的产品优势，而非口号。
- **数字鸿沟友好**：零安装、零注册、零费用，老旧手机、低配电脑均可使用。

## 四、C — Competitors（竞争）

### 4.1 竞品格局

| 竞品 | 类型 | 优势 | 劣势 |
|---|---|---|---|
| **作业帮口算 / 小猿口算** | 大厂 App | 题库大、拍照批改准、品牌强、用户基数大 | ① 需注册登录；② 功能繁杂（直播课、商城）；③ **核心能力围绕"屏幕拍题批改"，不解决"要交纸质本子"**；④ 部分功能付费；⑤ 有广告与推送 |
| **一起作业 / 一起学** | 家校 App | 与学校作业流程打通 | ① 需学校统一接入，个人家长用不起来；② 强制注册与班级绑定；③ 体验重 |
| **纸质口算题卡** | 线下教辅 | 便宜、即买即用、无屏幕 | ① 题目**固定不可定制**；② 买来就是整本，无法只练除法；③ 错题仍需手抄；④ 无任何统计 |
| **微信小程序类口算工具** | 小程序 | 免安装、传播快 | ① 功能普遍单薄（仅屏幕答题）；② **打印能力弱**；③ 广告多；④ 数据在别人服务器上 |

| 自动批改 | ✅（屏幕/拍照） | ❌ | ✅（屏幕） | ✅（屏幕 + 答案页） |
| 错题本与重练 | ⚠️ 部分付费 | ❌ | ⚠️ 有限 | ✅ |

### 4.3 竞争劣势的诚实评估

我们不做粉饰，客观承认本项目的短板：

| 劣势 | 影响 | 应对 |
|---|---|---|
| **无大厂题库与拍照批改** | 无法批改孩子写在纸上的字 | 我们的纸质卷**配套答案页**，家长对照即可；拍照 OCR 明确列入 Won't（技术不可控） |
| **无品牌与用户基数** | 冷启动难 | 走"家长群口碑"路线，见 D 部分 |
| **本地存储有丢失风险** | 换设备/清缓存会丢数据 | 提供**数据导出/导入 JSON** 功能作为兜底 |
| **无云端同步** | 手机和平板数据不互通 | 明确列为下一版本规划；当前版本用"导出/导入"过渡 |

### 4.4 差异化定位（一句话）

> **别人做"在手机上刷口算"，我们做"把口算作业打印出来"。**
>
> 大厂竞品都在抢"屏幕批改"这个入口，但它们**恰恰绕开了家长每天真实发生的那一步——
> 把 30 道题交到孩子手上，再把写好的本子交回给老师**。
> 口算小达人用浏览器原生打印能力补上这一步，而且免注册、免费用、数据不外传。

### 4.5 创新点

1. **纸质 + 数字双通道**：同一套题目既可屏幕练习（自动批改），也可打印成卷（对接学校作业流程），二者共用同一份记录与错题本。
2. **举一反三变式题**：错题不是简单重做，而是生成同知识点的**新题**，用于验证"真会了"而非"记住答案了"。
3. **零服务端架构**：无后端 = 无隐私风险 + 无服务器成本 + 无宕机可能，部署在静态托管上即可支撑任意用户量。

## 五、D — Delivery（推广）

### 5.1 推广目标

| 阶段 | 时间 | 目标 |
|---|---|---|
| 冷启动 | 第 1–2 周 | 拿到 **10 位真实家长**的试用反馈 |
| 口碑扩散 | 第 3–6 周 | 通过家长群扩散至 **50+ 用户**，收集 ≥ 20 份有效反馈 |
| 验证 | 课程汇报前 | 至少 **1 位小学数学老师**背书，证明"纸质卷"路线成立 |

### 5.2 推广渠道与打法

| # | 渠道 | 具体打法 | 预期效果 |
|---|---|---|---|
| D1 | **Gitee Pages 在线试用** | 部署静态站点，生成**二维码**印在任何物料上，扫码即用，无需下载 | 解决"试用门槛"，是推广的地基 |
| D2 | **家长群 / 班级群口碑传播** | 先给 3 位受访家长用，请他们在班级群晒"今天 30 秒出完卷"的截图 | 家长群转化率最高的渠道——**同类人群的实证** |
| D3 | **老师背书** | 把打印出的 A4 卷子拿给老师看，说明"题目按知识点定制、可全班统一" | 老师一句话 > 家长自推十句 |
| D4 | **公众号 / 小红书图文** | 以"陪写作业崩溃现场"为切入，讲"每天省 15 分钟"的具体方法 | 长尾获客 |
| D5 | **开学季时间窗** | 在开学前两周集中推广（家长焦虑峰值） | 提升单次曝光的转化率 |
| D6 | **课程汇报现场演示** | 第八次课公开演示，现场扫码即用，收集同学与老师的直接反馈 | 满足课程"真实用户反馈"要求 |

### 5.3 推广物料清单

| 物料 | 内容 | 负责人 |
|---|---|---|
| 项目落地页 | 截图 + 使用介绍 + 二维码 + 获取方式 | 屠生豪 |
| 二维码 | 指向 Gitee Pages 在线地址 | 屠生豪 |
| 演示视频 | 90 秒：从出题到打印的全流程 | 周明灏 |
| 家长话术卡 | 3 句话讲清"能帮你省什么" | 黄磊 |
| 打印样张 | 一张真实的 A4 口算卷（含答案页） | 周明灏 |

### 5.4 留存策略

| 手段 | 说明 |
|---|---|
| **打卡天数与徽章** | 给孩子即时激励，形成每日打开习惯 |
| **周报式学情卡片** | 每周生成一张"本周正确率 + 进步曲线"卡片，家长可截图分享（**分享即推广**） |
| **错题本"清零"进度** | 错题本显示"还有 7 道错题待攻克"，制造完成感 |
| **零打扰** | 不推送、不弹窗、不发短信——用"安静"作为对家长的承诺 |

### 5.5 发布合规与可持续性

- 部署于 **Gitee Pages**，公网可访问，保留至少 1 个月以备检查（课程要求）；
- 项目开源（MIT），代码托管于 Gitee，接受外部反馈与贡献；
- **不做任何儿童个人信息的收集与上传**，从设计上规避未成年人数据合规风险。

## 六、NABCD 一句话总结

> **N**｜家长每天被迫花 15~30 分钟做"出题—抄题—批改—抄错题"的重复劳动，这是一项高频、刚性、无良好替代方案的负担。
> **A**｜我们用参数化出题引擎自动组卷，用浏览器原生能力完成即时批改与 **A4 打印出卷**，用本地存储实现错题自动归档与举一反三。
> **B**｜家长每天从 15 分钟变成 30 秒，孩子获得精准加练与即时反馈，且三年一贯、完全免费、数据不外传。
> **C**｜大厂竞品在"屏幕刷题"赛道激烈竞争，却绕开了"要交纸质本子"这个真实场景；**A4 打印出卷 + 举一反三 + 免注册本地化**是我们的差异化切口。
> **D**｜以 Gitee Pages 扫码即用为地基，走"家长群口碑 → 老师背书 → 开学季时间窗"的传播路径。
