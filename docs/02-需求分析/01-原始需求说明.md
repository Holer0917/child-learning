## 一、业务背景

### 1.1 选题出处

本项目选题来自《软件工程》实践课程「软件工程项目选题参考」第 **2** 题：

> **2、儿童学习**
>
> 小明的妈妈近期很郁闷，小明上小学后，老师要求每天完成 30 道口算题，
> 每天出题改题成了一个大负担，"有个可以出题的软件就好了"小明妈妈这么想。
> 真的可以做出一个解决小明妈妈烦扰的软件吗？
>
> **提示**：小明现在一年级，小明妈妈可是希望买一个软件可以用三年的。
> 你的用户可以询问任何一个小朋友在读书的家长，看看他们对这个软件有什么需求。
>
> **注意**：该题目的完成形式可以是 App、小程序，但是**必须要完成最终的发布**，
> 可以让普通用户通过互联网直接试用。

### 1.2 业务场景还原

```
┌──────────────────────────────────────────────────────────────┐
│  场景：一个普通工作日的晚上 19:30                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ① 老师布置作业：「今天口算 30 题，明天交本子」                 │
│                          ↓                                   │
│  ② 妈妈翻开口算题卡，发现今天该练的是"混合运算"                 │
│     但孩子最近错的都是"退位减法"，题卡上却没有单独的退位减法     │
│                          ↓                                   │
│  ③ 妈妈决定自己出题，手写 30 道 —— 耗时约 10 分钟              │
│     中途还要保证不重复、难度适中、答案算对                      │
│                          ↓                                   │
│  ④ 孩子做题 —— 15 分钟                                        │
│                          ↓                                   │
│  ⑤ 妈妈逐题批改 —— 耗时约 5 分钟，且需高度集中注意力            │
│                          ↓                                   │
│  ⑥ 把错题抄到错题本上 —— 耗时约 3 分钟                         │
│                          ↓                                   │
│  ⑦ 孩子订正，妈妈讲题 —— 10 分钟                               │
│                                                              │
│  家长净投入的"机械劳动"时间：10 + 5 + 3 = 18 分钟              │
│  且这 18 分钟每天都在重复，一学期（100 天）≈ 30 小时            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

| RN-10 | "他做题磨磨蹭蹭，一个小时做 30 道" | 系统应记录**答题用时** | 家长 C |

## 四、术语表

> 术语表是需求文档的地基——它保证 3 位组员、老师、家长对同一个词的理解一致。

| 术语 | 英文 / 标识 | 定义 |
|---|---|---|
| **口算** | Mental Arithmetic | 不借助纸笔竖式演算、直接得出结果的计算练习。区别于"笔算"。 |
| **知识点** | Knowledge Point / `KP` | 出题的最小粒度单位，如"20 以内进位加法"。本系统共定义 24 个。 |
| **知识点大纲** | Syllabus | 全部知识点的集合及其年级、难度、前置关系。 |
| **档案** | Profile | 一个孩子的独立数据空间，包含其练习记录、错题、统计。 |
| **组卷** | Paper Generation | 根据知识点、题量、难度等参数生成一份题目的过程。 |
| **卷子 / 试卷** | Paper | 一次组卷的产物，包含若干道题目，对应一次练习或一张打印纸。 |
| **题目** | Question | 一道具体的口算题，如 `37 + 25 = ?`。 |
| **题型** | Question Type | 题目的结构类型：横式、竖式、比较大小、填空、连算。 |
| **作答记录** | Attempt | 用户对某道题的一次作答，含用户答案、是否正确、耗时。 |
| **练习记录** | Practice Session | 一次完整的答题过程，含卷子、全部作答、总用时、得分。 |
| **正确率** | Accuracy | 一次练习中答对题数 ÷ 总题数。 |
| **错题** | Wrong Question | 答错的题目，及其知识点、错因归类、首次答错时间。 |
| **错题本** | Mistake Book | 全部错题的集合，支持按知识点筛选与重练。 |
| **举一反三** | Variant Generation | 依据错题的知识点与参数特征，生成同型新题的过程。 |
| **掌握度** | Mastery | 某知识点下"答对题数 ÷ 总作答题数"的加权值，用于表征熟练程度。 |
| **打印卷** | Printable Sheet | 排版为 A4 版式、可直接打印的题目页。 |
| **答案页** | Answer Sheet | 与打印卷配套的答案页，供家长对照批改。 |
| **竖式** | Vertical Form | 数字上下对齐的算式排版方式，用于笔算。 |
| **PWA** | Progressive Web App | 可"添加到主屏幕"、可离线访问的网页应用。 |
| **数据导出** | Data Export | 把本地档案导出为 JSON 文件，用于备份与迁移。 |
| **题量** | Question Count | 组卷时**请求**的题目数量（如"30 道"）。与"实际题量"（预览删除后保留的题数）区分。 |
| **作答题数** | Answered Count | 一次练习中**提交了非空、合法答案**的题目数，不含跳过；同题纠错重试不重复计数。 |

## 五、范围界定（What's In / What's Out）

### 5.1 范围内（In Scope）

- ✅ 小学 **1~3 年级**课内口算（加、减、乘、除、混合运算、分数与小数初步）
- ✅ 出题组卷（按年级 / 知识点 / 题型 / 题量 / 难度）
- ✅ 在线答题与即时判分
- ✅ 自动批改与成绩汇总
- ✅ 错题本、错题重练、举一反三
- ✅ 学情统计（正确率趋势、知识点掌握度、练习量）
- ✅ A4 打印出卷（含答案页）
- ✅ 多孩子档案
- ✅ 数据导出 / 导入

### 5.2 范围外（Out of Scope）

| 不做的事 | 原因 |
|---|---|
| ❌ 语文、英语、应用题、奥数 | 与"每天 30 道口算题"的核心场景无关，会稀释项目 |
| ❌ 拍照批改手写答案（OCR） | 技术复杂度远超 6 周可完成范围 |
| ❌ 语音读题 | 浏览器语音合成质量不稳定，且非核心痛点 |
| ❌ 云端账号与多端同步 | 需要服务端，与"零服务端、数据不外传"的架构决策冲突 |
| ❌ 排行榜、好友挑战、社区 | 引入社交与内容审核成本，且对"省家长时间"无贡献 |
| ❌ 付费与内购 | 课程项目，且"完全免费"是差异化卖点 |
| ❌ 老师端班级管理后台 | 需服务端，且老师是次要用户 |
| ❌ 广告 | 与"儿童友好、零打扰"的产品承诺冲突 |

## 七、成功标准

> 如何判断这个项目"做成了"？以下标准在需求评审会上被确认。
> **S1~S6 是软件需求层面的可验收指标**；S7~S8 属课程交付活动（用户验证与推广），
> 不是软件本身的验收条件，已移至 [验证计划](#八验证计划非软件需求)。

| # | 成功标准 | 度量方式 |
|---|---|---|
| S1 | 家长能在 **30 秒内**完成"出卷 → 打印" | 可用性测试计时 |
| S2 | 家长能在 **3 次点击内**完成"出题 → 开始答题" | 点击路径计数 |
| S3 | 生成 30 道题的正确率 **100%** | 1000 道抽样人工核对 |
| S4 | 出题响应时间 **< 50ms** | 性能测试 |
| S5 | 首屏加载时间 **< 1s**（本地） | Lighthouse |
| S6 | 打印卷在 A4 纸上的排版**不错行、不截断** | 真实打印验证 |

## 八、验证计划（非软件需求）

> 本节记录课程要求的**过程性验证活动**。它们衡量的是"项目推广与用户验证做得如何"，
> 不是软件功能的验收标准，因此不进入 SRS 的需求基线，也不参与需求优先级排序。

| # | 验证活动 | 目标 | 度量方式 | 阶段 |
|---|---|---|---|---|
| V1 | 真实家长试用 | 至少 **10 位**家长实际使用并收集 **≥ 20 份**有效反馈 | 反馈表统计 | 发布后（第七~八次课） |
| V2 | 教师认可 | 至少 **1 位**小学数学老师确认题目符合教材进度 | 老师访谈确认 | 发布前（第六次课） |
| V3 | 公网可用性 | 普通用户可通过互联网直接访问并完成一次出卷 | 提供可访问 URL + 陌生用户走查 | 第七次课 |

> **为什么单列**：S7/S8 若留在"成功标准"里，会与 FR/NFR 的验收混淆——
> 它们是项目推广指标，即使软件全部功能达标，也可能因为没找到 10 位家长而"不成功"；
> 反之亦然。分离后，需求验收只看 S1~S6 与 SRS 中的 AC，过程活动由本节单独考核。
