## 需求概览

| 模块 | 需求编号 | 条数 | 优先级 |
|---|---|---|---|
| M1 档案管理 | FR-01 ~ FR-03 | 3 | Must / Should |
| M2 知识点与题库 | FR-04 ~ FR-06 | 3 | Must / Should |
| M3 出题组卷 | FR-07 ~ FR-11 | 5 | Must / Should |
| M4 在线答题 | FR-12 ~ FR-15 | 4 | Must / Should / Could |
| M5 自动批改与成绩 | FR-16 ~ FR-17 | 2 | Must |
| M6 错题本与举一反三 | FR-18 ~ FR-21 | 4 | Must / Should |
| M7 学情统计 | FR-22 ~ FR-24 | 3 | Should / Could |
| M8 打印出卷 | FR-25 ~ FR-26 | 2 | **Must（核心）** |
| M9 数据管理 | FR-27 ~ FR-28 | 2 | Must / Should |
| **合计** | | **28** | Must 16 / Should 10 / Could 2 |

**非功能需求**：NFR-01 ~ NFR-10（性能 / 易用性 / 可靠性 / 兼容性 / 安全性 / 可访问性 / 可维护性 / 可移植性 / 数据容量 / 打印质量）

**时间相关需求**：TR-01 ~ TR-10（计时、倒计时、跨天归属、打卡更新、统计范围、数据保留、备份命名、大纲变更、主题跟随）

**故障模式**：FM-01 ~ FM-12（存储不可用 / 数据损坏 / 空间不足 / 出题枯竭 / 参数矛盾 / 排版溢出 / 打印深色 / 导入非法 / 答案缺失 / 除零 / 脚本异常 / 离线访问）

**边界条件**：题量 5~100、档案 ≤ 3、记录 500+2000、错题 ≤ 500、倒计时 1~60 分钟、视口 360~1920px、导入 ≤ 5MB

## 需求分析流程

```
选题场景（教材第2题）
      │
      ▼
 ① 场景解读 ──► 收窄范围至「1~3年级口算」
      │
      ▼
 ② 用户访谈 ──► 3 位家长 + 1 位老师，提炼原始需求 12 条
      │            └─► 同时记录「无依据的假设」并否定
      ▼
 ③ AI 辅助建模 ──► 生成候选需求 18 条 → 人工核实保留 12 条
      │            └─► 现行知识点清单逐项计数：8 + 8 + 8 = 24
      ▼
 ④ 编写验收标准 ──► EARS 句式 161 条，AI 生成的 17 条模糊表述已量化
      │
      ▼
 ⑤ 优先级排序 ──► MoSCoW 分级，与使用频率逐条对照
      │
      ▼
 ⑥ 需求评审 ──► 13 项问题（3 遗漏 / 4 不可测试 / 3 歧义 / 1 优先级 / 2 非功能）
      │
      ▼
 ⑦ 补齐非功能与异常 ──► 输入输出格式、时间需求、故障模式、边界值
      │
      ▼
 ⑧ 人工核实 ──► 60 项核实，纠正 5 处事实错误，删除 4 项无源数据
      │
      ▼
 ⑨ 基线化 ──► V1.3 需求修订稿（2026-10-19 依评分反馈修订），等待人工复核
```
