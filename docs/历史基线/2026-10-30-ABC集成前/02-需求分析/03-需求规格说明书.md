## 1. 引言

### 1.1 编写目的

本文档定义「口算小达人」的全部软件需求，作为设计、实现、测试与验收的唯一依据。
文档面向：项目组成员、课程指导教师、评审人员。

### 1.2 项目背景

小明的妈妈每天需要为读小学的孩子手工出 30 道口算题、逐题批改、抄录错题，
耗时 15~30 分钟。本项目的目标是把这个过程压缩到 1 分钟以内。

**原需求阶段的业务背景陈述**（源自 [用户访谈材料](02-用户访谈原始记录.md)，历史核实状态以材料中的说明为准）：

- 口算作业是学校老师**强制布置**的纸面作业，家长无法回避；
- 家长的痛点不在"孩子做题"，而在"**出题 + 批改 + 抄错题**"这三项重复劳动；
- 家长希望**一个软件用三年**，覆盖 1~3 年级。

V1.4 范围说明：保留这些背景以追溯原选择；本期按用户指令取消纸面输出，交付目标集中于在线练习与减轻出题/批改/整理错题负担，不承诺替代纸质作业提交。

### 1.3 产品定位

> 面向小学 1~3 年级家长的**口算练习一站式工具**：出题、在线答题、批改、成绩历史、错题重练与学情统计。
> 免注册 · 免安装 · 数据全部留在本机 · 打开网页就能用。

### 1.4 术语定义

术语定义见 [原始需求说明 · 术语表](01-原始需求说明.md#四术语表)。本文档中，
**SHALL** 表示强制要求，**SHOULD** 表示建议要求，**MAY** 表示可选。

### 1.5 需求编号规则

| 前缀 | 含义 | 示例 |
|---|---|---|
| `FR-xx` | 功能性需求（Functional Requirement） | FR-07 智能组卷 |
| `NFR-xx` | 非功能性需求（Non-Functional Requirement） | NFR-01 响应时间 |
| `AC-xx.y` | 验收标准（Acceptance Criteria），x 对应需求号 | AC-07.3 |

## 2. 总体描述

### 2.1 用户角色

| 角色 | 说明 | 主要操作 |
|---|---|---|
| **家长**（主要用户） | 孩子的监护人，软件的决策者与操作者 | 建档案、出题、查看成绩历史和统计、管理错题 |
| **学生**（直接用户） | 1~3 年级小学生 | 屏幕答题、查看自己的成绩与徽章 |
| **老师**（次要用户） | 小学数学教师 | 与家长共同查看设备上的练习结果与统计；无教师专用入口或分发功能 |

> **设计说明**：本系统不设"账号"概念，因此没有"管理员"角色。
> 家长与学生在同一设备上通过"档案"区分，不做身份认证。

### 2.2 运行环境

| 项 | 要求 |
|---|---|
| 运行平台 | 现代浏览器（Chrome / Edge / Safari / Firefox 近两年版本） |
| 设备 | 手机（≥ 360px 宽）、平板、桌面电脑 |
| 网络 | 首次访问需联网加载；之后支持离线使用（PWA） |
| 存储 | 浏览器 localStorage，约 5MB 可用空间 |
| 服务端 | **无**（纯静态托管） |

### 2.3 设计与实现约束

| # | 约束 |
|---|---|
| DC-1 | 采用原生 HTML5 + CSS3 + ES Module 实现，**不引入任何第三方运行时依赖**。统计图表（折线图、条形图、热力格）以手写 SVG 实现，离线缓存以自写 Service Worker 实现，二者均不引入 ECharts、Chart.js、Workbox 等库 |
| DC-2 | 数据仅存储于浏览器本地，**不得向任何服务器上传用户数据** |
| DC-3 | 界面文案使用简体中文，面向儿童的部分不得使用生僻字 |
| DC-4 | 题目必须符合人教版小学数学教材的口算范围与进度，**不得超纲** |
| DC-5 | 所有计算答案必须准确无误 |
| DC-6 | 必须可通过静态托管部署并公网访问 |
| DC-7 | **已撤销**：原 A4 打印约束，见 CR-20261025-01；不再验收 |

### 2.4 假设与依赖

| # | 假设 / 依赖 | 风险 |
|---|---|---|
| AS-1 | 用户设备具备现代浏览器 | 低（覆盖主流设备） |
| AS-2 | 用户愿意使用浏览器而非 App | 中（通过 PWA 缓解） |
| AS-3 | Gitee Pages 服务持续可用 | 低 |
| AS-4 | **已撤销**：原桌面打印假设 | 不再适用 |
| AS-5 | 用户不清空浏览器数据 | 中（通过数据导出缓解） |

## 3. 功能性需求

> 每条需求包含：**用户故事**（作为…我希望…以便…）、**优先级**、**验收标准**（EARS 句式）。
> 优先级采用 MoSCoW：Must / Should / Could / Won't。

---

### 模块 M1：档案管理

#### FR-01 创建孩子档案

**用户故事**：作为家长，我希望为每个孩子建立一个独立档案，以便分别记录他们的练习情况。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 C-1（家长 C，两个孩子） |

**验收标准**

1. **AC-01.1** THE System SHALL 提供"新建档案"功能入口。
2. **AC-01.2** WHEN 家长新建档案时，THE System SHALL 允许输入孩子昵称。
3. **AC-01.3** WHEN 家长新建档案时，THE System SHALL 允许选择孩子所在年级（1 / 2 / 3 年级）。
4. **AC-01.4** WHEN 家长新建档案时，THE System SHALL 允许为孩子选择一个头像标识。
5. **AC-01.5** THE System SHALL 允许在同一设备上创建多个档案。
6. **AC-01.6** WHEN 家长未输入昵称时，THE System SHALL 使用默认昵称"小朋友"。

#### FR-02 切换与编辑档案

**用户故事**：作为家长，我希望能在多个孩子之间快速切换，以便分别为他们安排练习。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 C-1 |

**验收标准**

1. **AC-02.1** THE System SHALL 在全部主界面的顶部导航栏固定显示当前档案的头像与昵称，点击该区域即进入档案切换（顶部导航栏在滚动时保持吸顶，不随内容滚出视口）。
2. **AC-02.2** WHEN 家长点击切换入口时，THE System SHALL 列出全部已创建的档案。
3. **AC-02.3** WHEN 家长选择某个档案时，THE System SHALL 将该档案设为当前档案并刷新界面数据。
4. **AC-02.4** THE System SHALL 允许家长修改档案的昵称、年级与头像。
5. **AC-02.5** WHEN 家长切换档案后，THE System SHALL 仅显示当前档案的练习记录、错题与统计。

#### FR-03 删除档案

**用户故事**：作为家长，我希望删除不需要的档案，以便保持档案列表整洁。

| 属性 | 值 |
|---|---|
| 优先级 | Should |
| 来源 | 派生需求 |

**验收标准**

1. **AC-03.1** THE System SHALL 提供删除档案的功能入口。
2. **AC-03.2** WHEN 家长点击删除时，THE System SHALL 弹出二次确认提示，说明该档案下的全部数据将被删除。
3. **AC-03.3** WHEN 家长确认删除时，THE System SHALL 删除该档案及其全部练习记录、错题与统计。
4. **AC-03.4** IF 被删除的档案是当前档案，THEN THE System SHALL 自动切换到剩余档案中的第一个。
5. **AC-03.5** IF 删除后已无任何档案，THEN THE System SHALL 引导家长创建新档案。

### 模块 M2：知识点与题库

#### FR-04 知识点大纲浏览

**用户故事**：作为家长，我希望看到 1~3 年级的全部口算知识点，以便了解软件能覆盖哪些内容。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 D-1（老师：必须对标教材） |

**验收标准**

1. **AC-04.1** THE System SHALL 按年级（一年级 / 二年级 / 三年级）分组展示全部知识点。
2. **AC-04.2** THE System SHALL 为每个知识点显示名称、所属年级与难度星级。
3. **AC-04.3** THE System SHALL 覆盖至少 24 个知识点，且每个年级不少于 6 个。
4. **AC-04.4** THE System SHALL 为每个知识点提供一句"这个知识点在练什么"的说明。
5. **AC-04.5** THE System SHALL 标记出该知识点在当前年级下的学习顺序。

#### FR-05 知识点筛选与检索

**用户故事**：作为家长，我希望快速找到某个知识点，以便针对孩子的薄弱环节出题。

| 属性 | 值 |
|---|---|
| 优先级 | Should |
| 来源 | 访谈 B-1 |

**验收标准**

1. **AC-05.1** THE System SHALL 提供按年级筛选知识点的功能。
2. **AC-05.2** THE System SHALL 提供按关键词搜索知识点的功能。
3. **AC-05.3** WHEN 家长输入关键词时，THE System SHALL 实时过滤并显示匹配的知识点。
4. **AC-05.4** THE System SHALL 提供"全选 / 全不选 / 反选"的批量操作。
5. **AC-05.5** THE System SHALL 提供"按年级一键勾选"的快捷操作。

#### FR-06 教材对标校验

**用户故事**：作为老师，我希望系统不会出现超纲题目，以便家长出的题与课堂教学保持一致。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 D-1（老师：超纲是最常见的问题） |

**验收标准**

1. **AC-06.1** THE System SHALL 为每个知识点定义明确的数值取值范围约束。
2. **AC-06.2** WHEN 生成题目时，THE System SHALL 严格遵守该知识点定义的范围约束。
3. **AC-06.3** THE System SHALL 确保生成结果始终满足知识点约束（如"20 以内进位加法"的结果不超过 20）。
4. **AC-06.4** THE System SHALL 提供"年级默认知识点组合"，避免家长误选超纲知识点。

### 模块 M3：出题组卷

#### FR-07 智能组卷

**用户故事**：作为家长，我希望系统自动生成一份题目，以便省去手写出题的时间。

| 属性 | 值 |
|---|---|
| 优先级 | **Must（核心）** |
| 来源 | 访谈 A-1、B-1、C-5；教材原文 |

**验收标准**

1. **AC-07.1** THE System SHALL 提供"开始出题"功能入口。
2. **AC-07.2** WHEN 家长发起出题时，THE System SHALL 依据选定的知识点、题量、题型与难度生成题目。
3. **AC-07.3** THE System SHALL 在 **50 毫秒内**完成一份题目的生成。
4. **AC-07.4** THE System SHALL 保证同一份卷子内不出现完全相同的题目，判重采用 §5.4.5 定义的错题去重键（同知识点、同题型、同运算种类、同操作数；加法与乘法横式交换操作数视为同题）。
5. **AC-07.5** THE System SHALL 保证每道题的答案计算结果准确无误。
6. **AC-07.6** WHEN 家长未指定知识点时，THE System SHALL 默认使用当前档案年级的全部知识点。

#### FR-08 题量设置

**用户故事**：作为家长，我希望自由设置题量，以便匹配老师当天布置的作业量。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 A-1、B-1 |

**验收标准**

1. **AC-08.1** THE System SHALL 提供题量设置选项，包含 10 / 20 / 30 / 50 四档预设值。
2. **AC-08.2** THE System SHALL 允许家长自定义题量，取值范围为 5 ~ 100。
3. **AC-08.3** WHEN 家长自定义题量超出范围时，THE System SHALL 提示并自动修正到合法范围。
4. **AC-08.4** THE System SHALL 在出题前显示"本次将生成 N 道题"的确认信息。

#### FR-09 难度分级

**用户故事**：作为家长，我希望调整题目难度，以便让题目既不太简单也不太困难。

| 属性 | 值 |
|---|---|
| 优先级 | Should |
| 来源 | 访谈 A-9（家长：孩子直接哭） |

**验收标准**

1. **AC-09.1** THE System SHALL 为每道题定义 1~3 星的难度等级。
2. **AC-09.2** THE System SHALL 提供"简单 / 适中 / 挑战"三档难度设置。
3. **AC-09.3** WHEN 家长选择"简单"时，THE System SHALL 生成的 1 星题目占实际题量的比例不低于 70%（所需题数向上取整）；若所选知识点不支持该比例，出题前提示并要求重新选择知识点或难度，不得引入未选知识点。
4. **AC-09.4** WHEN 家长选择"挑战"时，THE System SHALL 生成的 3 星题目占实际题量的比例不低于 50%（所需题数向上取整）；若所选知识点不支持该比例，出题前提示并要求重新选择知识点或难度，不得引入未选知识点。
5. **AC-09.5** THE System SHALL 在组卷结果中展示本次卷子的平均难度星级，取值为全部题目星级的算术平均值，保留一位小数（四舍五入），并在数值后附星级图示。

#### FR-10 题型选择

**用户故事**：作为家长，我希望选择题目形式，以便匹配老师要求的作业格式。

| 属性 | 值 |
|---|---|
| 优先级 | Should |
| 来源 | 访谈 B-3（家长 B：还要做竖式） |

**验收标准**

1. **AC-10.1** THE System SHALL 支持以下题型：横式（`37 + 25 = □`）、竖式、比较大小（`37 + 25 ○ 60`）、填空（`□ + 25 = 62`）、连算（`12 + 8 - 5 = □`）。
2. **AC-10.2** THE System SHALL 允许家长勾选一种或多种题型。
3. **AC-10.3** WHEN 家长勾选多种题型时，THE System SHALL 按比例混合生成题目。
4. **AC-10.4** WHEN 家长勾选竖式题型时，THE System SHALL 以竖式版式渲染题目。
5. **AC-10.5** THE System SHALL 为每个知识点标注其支持的全部题型。

#### FR-11 组卷结果预览与调整

**用户故事**：作为家长，我希望在开始练习前先看看题目，以便确认题目合适。

| 属性 | 值 |
|---|---|
| 优先级 | Should |
| 来源 | 派生需求 |

**验收标准**

1. **AC-11.1** WHEN 题目生成完成后，THE System SHALL 展示全部题目供家长预览。
2. **AC-11.2** THE System SHALL 在预览页显示本次卷子的题量、平均难度与知识点分布；知识点分布以"知识点名称 + 该知识点题数 + 占实际题量百分比（保留整数）"的列表形式呈现，按题数降序排列。
3. **AC-11.3** THE System SHALL 提供"重新生成"按钮。
4. **AC-11.4** WHEN 家长点击"重新生成"时，THE System SHALL 生成一份全新的题目集合。
5. **AC-11.5** THE System SHALL 允许家长删除单道不满意的题目。
6. **AC-11.6** THE System SHALL 提供"查看答案"开关，默认关闭。

### 模块 M4：在线答题

#### FR-12 答题界面

**用户故事**：作为学生，我希望在屏幕上直接答题，以便立刻知道对错。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 A-3 |

**验收标准**

1. **AC-12.1** WHEN 家长或学生点击"开始答题"时，THE System SHALL 进入答题界面。
2. **AC-12.2** THE System SHALL 一次展示一道题，并显示当前进度（第 N / 共 M 题）。
3. **AC-12.3** THE System SHALL 提供数字键盘供触屏设备输入答案。
4. **AC-12.4** THE System SHALL 支持物理键盘直接输入数字、`-`、`.`、`/` 与回车提交。
5. **AC-12.5** THE System SHALL 在题目区域使用不小于 32px 的字号。
6. **AC-12.6** THE System SHALL 提供"跳过"按钮，允许暂时跳过当前题目。
7. **AC-12.7** THE System SHALL 提供"退出练习"按钮，并在退出前二次确认。

#### FR-13 即时判分

**用户故事**：作为学生，我希望答完立刻知道对不对，以便及时纠正。

| 属性 | 值 |
|---|---|
| 优先级 | Must |
| 来源 | 访谈 A-3 |

**验收标准**

1. **AC-13.1** WHEN 学生提交一道题的答案时，THE System SHALL 立即判定对错。
2. **AC-13.2** WHEN 答案正确时，THE System SHALL 显示绿色正确反馈并自动进入下一题。
3. **AC-13.3** WHEN 答案错误时，THE System SHALL 显示红色错误反馈并展示正确答案。
4. **AC-13.4** WHEN 答案错误时，THE System SHALL 允许学生重新作答一次（"再试一次"）。
5. **AC-13.5** THE System SHALL 在判分过程中不产生超过 100 毫秒的界面卡顿。
6. **AC-13.6** THE System SHALL 记录每道题的作答耗时。

#### FR-14 倒计时与计时

**用户故事**：作为家长，我希望知道孩子做题用了多久，以便区分"不会"与"磨蹭"。

| 属性 | 值 |
|---|---|
| 优先级 | Should |
| 来源 | 访谈 C-2（家长 C：想知道是磨蹭还是不会） |

**验收标准**

## 4. 输入 / 输出与数据格式定义

> 对应评分项「可验证性与规范性：输入/输出数据格式定义清楚」。

### 4.1 用户输入定义

| 输入项 | 来源界面 | 类型 | 取值范围 / 格式 | 校验规则 | 非法输入的处理 |
|---|---|---|---|---|---|
| 孩子昵称 `profile.name` | 档案管理 | 字符串 | 1~12 个字符，允许中文/字母/数字/emoji | 去除首尾空格后非空 | 为空时使用默认值"小朋友" |
| 年级 `profile.grade` | 档案管理 | 枚举整数 | `1` / `2` / `3` | 必须为枚举值之一 | 非法值回落为 `1` |
| 头像 `profile.avatar` | 档案管理 | 字符串 | 预置 emoji 列表中的一项 | 必须来自预置列表 | 非法值使用列表首项 |
| 知识点集合 `kpIds` | 出题台 | 字符串数组 | `G1-01` ~ `G3-08`，长度 ≥ 1 | 每项必须存在于知识点大纲中 | 过滤掉不存在的编号；若全部非法则拒绝出题并提示"请至少选择一个知识点" |
| 题量 `count` | 出题台 | 整数 | **5 ~ 100**，预设 10/20/30/50 | 必须为整数 | 超出范围时自动钳制到边界并在界面提示实际题量 |
| 难度 `difficulty` | 出题台 | 枚举字符串 | `easy` / `normal` / `hard` | 必须为枚举值之一 | 非法值回落为 `normal` |
| 题型集合 `types` | 出题台 | 字符串数组 | `horizontal` / `vertical` / `compare` / `fill` / `chain` | 必须为枚举值之一 | 非法值忽略；若与知识点无交集，自动回退为该知识点支持的全部题型 |
| 答题输入 `answer` | 答题界面 | 字符串 | 见 4.2 | 见 4.2 | 见 4.2 |
| 搜索关键词 `keyword` | 知识点页 | 字符串 | 0~20 字符 | 无 | 无匹配时展示"没有找到相关知识点" |
| 倒计时时长 `limitMs` | 出题台 | 整数（毫秒） | **60000 ~ 3600000**（界面输入 1~60 分钟后换算） | 必须为整数 | 超出范围时钳制到边界 |
| 导入文件 | 设置页 | File（`.json`，UTF-8） | ≤ 5 MB，格式见 4.4 | 见 4.4 | 见 4.4 |

### 4.2 答题输入格式与规范化规则

| 知识点类型 | 输入格式 | 允许的等价写法 | 规范化后的比较形式 |
|---|---|---|---|
| 整数运算 | 十进制整数，可带负号 | `624`、`0624`、`624.0` | `624` |
| 有余数除法 | `商余余数`（半角） | `9余2`、`9余 2`、`9 余2` | `9余2` |
| 分数 | `分子/分母` 或纯整数（结果为整数时） | `2/4`、`1/2`、`1` | 约分后的最简形式 `1/2`、`1` |
| 一位小数 | 十进制小数 | `3.5`、`3.50`、`.5`、`0.5` | 去尾随零后 `3.5`、`0.5` |
| 比较大小 | 单个符号 | `<`、`>`、`=`、全角 `＜＞＝`、中文 `﹤﹥` | 半角符号 |
| 全部类型 | 空串 / 仅空白字符 | — | 判定为"未作答"，不计入答错，计入跳过 |

**判分容错原则**：若用户答案与标准答案**数值相等**（如整数题答 `624.0`、小数题答 `3` 而标准答案为 `3.0`），一律判为正确——儿童不应因书写格式丢分。

### 4.3 系统输出定义

| 输出项 | 输出场景 | 格式 | 示例 |
|---|---|---|---|
| 题目文本 | 答题 / 在线预览 | 字符串，含运算符与作答位 | `156 × 4 = ___` |
| 竖式版式 | 竖式题 | 结构化对象 `{rows: string[], width, answerDigits}`，每行**等宽补空格**对齐 | `{rows:[" 748","  ×5"], width:4}` |
| 标准答案 | 判分 / 答案页 | 字符串，格式同 4.2 的规范化形式 | `624`、`9余2`、`1/2`、`3.5`、`>` |
| 成绩结算 `SessionResult` | 练习结束 | 对象，字段见 4.5 | — |
| 练习记录 | 历史页 | 列表，按 `finishedAt` 倒序 | — |
| 统计数据 | 学情页 | 见 §5.4 统计口径 | — |
| 备份文件 | 导出 | JSON，见 4.4 | `kidsmath-backup-20260927.json` |

### 4.4 数据交换格式

**备份文件（导出 / 导入）**

```json
{
  "format": "kidsmath-backup",
  "version": "1.0",
  "exportedAt": "2026-09-27T10:00:00.000Z",
  "profiles": [
    { "id": "u1a2b3", "name": "小明", "grade": 3, "avatar": "🦊", "createdAt": 1758000000000 }
  ],
  "data": {
    "u1a2b3": {
      "sessions": [],
      "mistakes": [],
      "badges":   [ { "id": "streak7", "name": "坚持一周", "earnedAt": 1758000000000 } ]
    }
  },
  "settings": { "sound": false, "theme": "auto" }
}
```

**导入校验规则与失败处理**

| 校验项 | 通过条件 | 失败处理 |
|---|---|---|
| 文件大小 | ≤ 5 MB | 提示"文件过大，请选择由本软件导出的备份文件"，终止导入 |
| JSON 可解析 | `JSON.parse` 不抛异常 | 提示"文件格式不正确"，终止导入 |
| `format` 字段 | 严格等于 `"kidsmath-backup"` | 同上，终止导入 |
| `version` 字段 | 主版本号 ≤ 当前支持的版本 | 提示"备份文件版本过新，请升级软件后重试"，终止导入 |
| `profiles` 数组 | 存在且为数组，每项含 `id`/`name`/`grade` | 跳过非法项并计数，导入结束后提示"已跳过 N 条无效数据" |
| `grade` 取值 | ∈ {1,2,3} | 该项回落为 `1` 并计数 |

### 5.4 统计口径与去重规则

#### 5.4.1 题量与作答题数

题量为组卷时请求的题目数；实际题量为成功生成并经预览删除后保留的题目数。作答题数为提交非空、合法答案的题目数。每题的首次有效提交用于本次成绩，纠错重试不覆盖首次成绩。正确数 + 错误数 + 跳过数 = 实际题量。

#### 5.4.2 正确率与评价

正确率 = 正确数 / 实际题量 ×100%，展示保留一位小数，等级用未取整数值判定。实际题量为 0 时禁止开始练习，不产生成绩。平均每题耗时 = 有效提交题目的耗时总和 / 作答题数；无作答时显示“—”。

#### 5.4.3 知识点掌握度

掌握度 = 该知识点首次有效提交的正确数 / 有效作答数 ×100%，包含普通练习、错题重练与变式练习，排除跳过及同题纠错重试。无有效作答时显示“未练习”。≥85% 为良好，≥60% 且 <85% 为待加强，<60% 为薄弱。完整明细与摘要均参与累计统计，摘要保存分知识点正确数及作答数；已超出保留范围的数据不参与统计。

#### 5.4.4 趋势与打卡

趋势按 finishedAt 倒序选最近 7/30 次或全部已保留记录，再按时间升序绘图；同一时间按记录 id 排序。打卡以设备本地自然日为单位，至少提交一道有效答案的已结算练习才计一天，同日多次只计一天。连续天数从今天（今天未练习则从昨天）向前逐日计算。累计练习题数统计有效作答数，界面注明统计仅覆盖已保留数据。

#### 5.4.5 错题去重键

key 为规范化元组 [知识点编号, 题型, 运算种类, 操作数, 填空位置或比较目标] 的 JSON 序列化结果。整数去前导零，小数去尾随零，分数约分；加法、乘法横式交换操作数视为同题，减法、除法保留顺序；连算保留运算顺序及括号，填空保留空位，比较题保留比较目标。不同档案不合并。卷内默认采用此键去重，FM-04 二级去重仅放宽交换律；错题本始终使用此键。例：同知识点横式 37+25 与 25+37 合并，37−25 与 25−37 不合并。

## 8. 需求追踪矩阵（RTM）

逐项验收映射见 [08-需求验收用例清单](08-需求验收用例清单.md)；下表「测试用例」列的 `TC-AC-xx.y` 与正文 `AC-xx.y` 一一对应，每条用例均写明输入样例与判定阈值。旧 `TC-1xx~9xx` 区间编号已废止。

> `原始诉求（访谈原话 / 教材原文）` → `需求条目` → `验收标准` → `设计 / 测试`

> 「依据」列写明该需求**凭什么成立**——是用户原话、教材规定、访谈结论，还是评审意见。
> 无法写出来源的条目，就不该存在。
