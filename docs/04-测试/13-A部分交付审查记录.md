## 3. 集成时必须保留 B 部分成果

### I-01 公共文件不得整份覆盖

ZIP 的 `src/main.js:20～29、60～61、87` 增加统计路由的同时，未包含本地 `installKeyboardSupport()`、`initPwa()`，导航监听顺序也退回旧版。直接覆盖会移除 B 已完成的键盘支持初始化、PWA 初始化和离开页面时的导航处理。

ZIP 的 `assets/css/base.css` 缺少本地知识点搜索、自定义题量、预览统计与编辑、音效反馈、比较键盘、安全区和低高度横屏适配等规则。**应保留本地入口和样式，仅增补统计页导入/路由与 A 专属样式。**

### I-02 结算归档与重练攻克属于待接入的共享流程

依据分工 §2，A 提供适配器，黄磊统一接入 `src/app/quizSession.js`；队友未直接改共享结算文件符合分工，不能据此简单认定其漏交了该文件。

不过，ZIP 与当前本地代码组合后，尚无业务调用 `archiveSession()`；5 题全部首次答错并结算，历史保存 1 条，但错题数为 0。手动准备 5 道错题后发起重练并全部答对，已攻克数仍为 0。分别由 R01、R03 验证。

集成需要同时完成：首次错题归档、重练正确结果回写攻克状态、重练错误次数累加、跳过不改状态，以及同会话重复结算不重复写入。不能只在结算尾部增加一次普通归档就宣告重练闭合。应保留来源错题关联和会话恢复信息，并定义归档写入失败后的提示与重试。

### I-03 离线缓存与 C 部分数据契约

- 当前 `sw.js:6～16` 缓存清单没有 A 新增的 3 个领域模块和统计页。正式集成时需补入依赖、递增缓存版本，再复测离线和更新保留数据；B 旧版的离线验收不能直接作为合并版结果。
- A 使用 `mistakes:<profileId>` 保存 `{version, archivedSessions, items}`，并增加完整题目快照、来源会话和攻克日期。C 的备份/导入、逐字段校验、档案级联删除须覆盖这些字段及归档防重记录。该变化已在代码注释中提示，仍需写入统一数据契约与设计变更记录。
- A01 按分工复用了当前 `generator.dedupeKey`，但共享生成器的键与 SRS §5.4.5 包含题型/空位的规范仍有差异。这是既有需求与实现的一致性问题，应统一裁决和记录，不能只在 A 中偷偷更换键。

## 6. 建议推进顺序

1. 先修复重练题量、变式不足/截断、统计口径等已复现问题，并补针对性回归。
2. 由黄磊按约定统一接入结算归档和重练结果回写；共享入口与 CSS 只合并增量，保留 B 功能。
3. 将错题数据结构、防重索引与 C 的备份/恢复/档案删除契约对齐，再更新相应设计变更。
4. 补齐 Must/Should 对应的页面与流程；Could 的打卡/徽章最后处理，变更应显式记录。
5. 在本地运行 A+B 集成回归，覆盖普通练习→首次错题→重练答对/答错/跳过→攻克→清理→统计不被改写，以及 1/5/100 题、500 错题、变式不足、刷新/离线恢复、写入失败。
6. 获得后续发布指示后，再处理远端合并与测试站更新；本次审查不执行发布。
